\section{Choice of Topic and Data Source}

In this project, we chose to study \textbf{anomaly detection in HDFS (Hadoop Distributed File System) logs}. This topic is relevant because system logs play a crucial role in monitoring, maintaining, and securing distributed systems.

The data used comes from the \textbf{Kaggle} platform, specifically the LogHub HDFS dataset (HDFS\_v1). This dataset is widely used in the data science and machine learning community for log anomaly detection research.

\begin{itemize}
    \item \textbf{Dataset name:} HDFS Log Dataset (LogHub HDFS\_v1)
    \item \textbf{Source:} Kaggle (ayenuryrr/loghub-hdfs-hadoop-distributed-file-system-data)
    \item \textbf{Dataset objective:} Identify normal and abnormal behaviors in HDFS logs
    \item \textbf{Anomaly rate:} 2.93\% (16,838 anomalies out of 575,061 total instances)
\end{itemize}

The dataset contains four main files:
\begin{itemize}
    \item \texttt{anomaly\_label.csv}: BlockId with labels (Normal/Anomaly)
    \item \texttt{Event\_occurrence\_matrix.csv}: Event occurrence counts by BlockId
    \item \texttt{Event\_traces.csv}: Detailed event sequences
    \item \texttt{HDFS.log\_templates.csv}: Event template definitions
\end{itemize}

The choice of this dataset is motivated by its clear structure, the presence of a \textbf{target variable (normal / anomaly)}, its relevance to real-world distributed systems, and its direct connection to concepts studied in statistics and probability courses.

\section{Data Processing and Structuring}

Before any statistical analysis, we properly prepared the data to avoid interpretation errors and ensure reliable results.

\subsection{Data Loading and Merging}
The dataset was loaded using the KaggleHub API. We merged the anomaly labels with the event occurrence matrix using \texttt{BlockId} as the key. The label was encoded as binary: 0 for normal and 1 for anomaly.

\subsection{Data Cleaning and Feature Engineering}
\begin{itemize}
    \item Standardized column names and removed duplicates on \texttt{BlockId}
    \item Ensured consistent data types for \texttt{BlockId}
    \item Encoded labels: \texttt{Normal} $\rightarrow$ 0, \texttt{Anomaly} $\rightarrow$ 1
    \item Converted event counts to numeric, filling NaN with 0
    \item Engineered core features:
    \begin{itemize}
        \item \texttt{total\_count}: Sum of all event counts per block
        \item \texttt{unique\_events}: Number of distinct event types per block
        \item \texttt{max\_event\_count}: Maximum count of any single event per block
        \item \texttt{log\_total}: Natural logarithm of \texttt{total\_count} (log1p transformation)
    \end{itemize}
    \item Selected top-15 most frequent events for analysis
\end{itemize}

\subsection{Final Dataset Structure}
The final feature table contains 575,061 instances with 21 features:
\begin{itemize}
    \item \texttt{BlockId}: Unique identifier
    \item \texttt{y}: Target variable (0=normal, 1=anomaly)
    \item Core engineered features (4)
    \item Top-15 event columns by global frequency
\end{itemize}

\begin{techbox}[Feature Engineering Insight]
The log1p transformation ($\log(1 + x)$) was applied to \texttt{total\_count} to handle its skewed distribution and reduce the influence of extreme values. This transformation is particularly useful for count data that may contain zeros.
\end{techbox}

\section{Interpretation of Results}

Our comprehensive analysis reveals several key findings:

\begin{itemize}
    \item \textbf{Distribution Differences}: Anomalous instances often exhibit extreme values and greater dispersion compared to normal instances
    \item \textbf{Feature Relationships}: Strong linear relationships exist between some features (e.g., unique\_events and total\_count) in the normal class
    \item \textbf{Distributional Properties}: The data shows overdispersion, making Negative Binomial distributions more appropriate than Poisson for count data
    \item \textbf{Anomaly Detection}: Simple statistical methods (distribution p-values) can identify anomalies, with 25\% of anomalies having p-value < 0.01 vs. 0.7\% of normals
    \item \textbf{Predictive Modeling}: Logistic regression achieves near-perfect classification with appropriate feature engineering and preprocessing
\end{itemize}

\section{Conclusion}

This project demonstrated a comprehensive statistical and probabilistic analysis of HDFS logs for anomaly detection. We followed a systematic approach:

\begin{enumerate}
    \item \textbf{Data Preparation}: Imported, cleaned, and engineered features from raw HDFS logs
    \item \textbf{Exploratory Analysis}: Conducted univariate and multivariate analysis to understand data distributions and relationships
    \item \textbf{Distribution Fitting}: Investigated how well empirical distributions match theoretical probability laws
    \item \textbf{Regression Analysis}: Explored linear relationships between features in the normal class
    \item \textbf{Predictive Modeling}: Built and evaluated a logistic regression model for anomaly detection
\end{enumerate}

Key insights from our analysis:
\begin{itemize}
    \item Statistical methods provide a solid foundation for understanding log data patterns
    \item Feature engineering (especially derived metrics) significantly improves anomaly detection
    \item Distribution-based anomaly scoring offers a simple yet effective approach
    \item The class imbalance (2.93\% anomalies) must be carefully handled in modeling
\end{itemize}

This work demonstrates that statistical tools can identify significant differences between normal and abnormal behaviors, providing a foundation for more advanced methods in machine learning and anomaly detection. Future work could explore more complex models, additional feature engineering, and real-time anomaly detection systems.
